🔍 核心参数及作用详解

参数项                  设置值                      它的作用是什么？
----------------------------------------------------------------------------------------------------
mode                    "packet-up"                 分包上行模式。对各类固定隧道、中转机和 CDN 网关的
                                                    兼容性最好，能防止双向流在隧道中被强行切断。

scMaxEachPostBytes      1000000 (约1MB)             限制单次上行包的最大字节数。防止瞬间大流量把隧道的
                                                    缓冲区瞬间撑爆而触发限速。

scMinPostsIntervalMs    30 (毫秒)                   控制发包的最小时间间隔。让上行数据以平稳的节奏发送，
                                                    避免流量突发被运营商或网关的 QoS 策略标记。

xmux                    (整个复用模块)              多路复用与连接主动轮换核心。用来彻底根治“刚连上很
                                                    流畅，用一段时间就卡死/掉速”的顽疾。

  ↳ maxConcurrency      "16-32"                     并发子通道数。允许单条隧道同时并发 16 到 32 个子请
                                                    求，提升多线程加载和网页/视频并发时的吞吐量。

  ↳ maxConnections      0                           最大物理连接数。设为 0 代表不设硬性上限，由内核自动
                                                    托管维护（避免设置成具体数字导致客户端报错）。

  ↳ cMaxReuseTimes      "64-128"                    单条连接最大复用请求数。当一条连接处理的请求达到这
                                                    个次数后，会自动废弃并重建，防止单条连接寿命过长。

  ↳ hMaxRequestTimes    "600-900"                   HTTP 层的最大请求复用次数。双重保险，配合请求次数
                                                    到期主动“换马甲”。

  ↳ hMaxReusableSecs    "1800-3000" (30~50分钟)     单条连接的最长存活时间（秒）。即使没达到请求数上限，
                                                    时间到了也会自动无缝切换新连接，避开网关超时拦截。

XHTTP Manager V4.8.9
====================

本版本以用户此前提供的 V4.8.8 完整包为基础，保留原有管理器结构与功能，不以 V4.8.5 为基础，也不删减七种协议、Xray 核心管理、Cloudflare Tunnel、节点信息、订阅和卸载功能。

V4.8.9 主要调整：固定单实例目录
------------------------------
1. 新版唯一实例固定为 /etc/xhttp；管理器运行文件固定为 /usr/local/lib/xhttp；Xray 二进制固定为 /usr/local/bin/xray-xhttp；服务固定为 xhttp.service。
2. 不再自动选择或创建 /etc/xhttp-2、/etc/xhttp-3 等新实例目录。固定目录被其他程序占用且无法确认归属时，会停止并提示，不会偷偷换目录或覆盖不明文件。
3. 识别旧版 /etc/xhttp 标记中的错误版本值（例如 Ubuntu 24.04.5 LTS），前提是实例标记、config.json、state.json、专用 Xray 二进制和服务配置能相互对应；确认归属后自动把标记修正为 V4.8.9。
4. 订阅生成器不再因版本字段异常而过滤节点，改为检查实例名称、节点状态字段、端口和 UUID。主菜单也不再因旧版本号过滤有效节点。
5. 管理器启动时同步当前 ZIP 包中的 core.sh、tunnel.sh、local_sub_builder.py 和 local_sub_server.py，避免本地订阅继续使用旧生成器。
6. 卸载会清理固定 xhttp 主实例，并兼容清理可验证属于本项目的旧版 xhttp-N 目录、专属服务和二进制。继续保护 /etc/s-box/、sing-box.service、通用 Xray/Cloudflared 及其他项目资源。

安装 / 更新
------------
1. 将 ZIP 解压到 VPS。
2. 进入 XHTTP_Manager_V4.8.9 目录，以 root 执行：bash xhttp.sh
3. 后续可使用：xhttp
4. 新版只会管理 /etc/xhttp 这一套固定实例；再次安装/配置时使用同一目录和服务，不会创建 xhttp-2、xhttp-3。

重要说明
--------
- 当前代码的 Xray 服务配置仍采用一个 config.json / 一个活动入站的设计。再次执行“安装 / 配置节点”会更新这个固定实例的节点配置，不等同于在同一个 Xray 配置中同时叠加多个独立活动节点。历史 xhttp-N 可在卸载时清理；如果需要多个并行节点配置，需另行做多入站/多节点数据结构改造，不能仅靠固定目录改名实现。
- 本地订阅生成器仍能识别遗留且有效的 xhttp-N 状态目录，直到用户执行完整卸载清理。
- 本包完成本地静态检查和合成数据测试；没有在用户 VPS 上执行真实 systemd/OpenRC 安装、重启、Cloudflare 授权或客户端连接测试。请先备份 VPS，再测试更新/卸载。

入口修复补丁（本次更新）
----------------------
- 修复快捷命令文件 /usr/local/bin/xhttp 被意外清空（0 字节）后，管理器因“未知文件保护”而拒绝重建入口的问题。
- 运行本包的 `bash xhttp.sh` 时，如果检测到该路径是 0 字节普通文件，会先将其移至 /usr/local/bin/xhttp.empty-backup，再创建正确的快捷启动器。
- 如果备份目标已存在、原文件是符号链接，或原文件非空，程序不会按此规则覆盖它；其他程序的非空快捷命令仍受保护。
- 本补丁只针对入口恢复，不改动节点配置结构、协议实现、本地订阅格式或 Tunnel 行为。
