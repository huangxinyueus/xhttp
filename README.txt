🔍 核心参数及作用详解

参数项                  设置值                      它的作用是什么？
----------------------------------------------------------------------------------------------------
mode                    "packet-up"                 分包上行模式。对各类固定隧道、中转机和 CDN 网关的
                                                    兼容性最好，能防止双向流在隧道中被强行切断。

scMaxEachPostBytes      1000000 (约1MB)             限制单次上行包的最大字节数。防止瞬间大流量把隧道的
                                                    缓冲区瞬间撑爆而触发限速。

scMinPostsIntervalMs    30 (毫秒)                   控制发包的最小时间间隔。让上行数据以平稳的节奏发送，
                                                    避免流量突发被运营商或网关的 QoS 策略标记。

xmux                    (整个复用模块)              多路复用与连接主动轮换核心。用来彻底根治“刚连上很
                                                    流畅，用一段时间就卡死/掉速”的顽疾。

  ↳ maxConcurrency      "16-32"                     并发子通道数。允许单条隧道同时并发 16 到 32 个子请
                                                    求，提升多线程加载和网页/视频并发时的吞吐量。

  ↳ maxConnections      0                           最大物理连接数。设为 0 代表不设硬性上限，由内核自动
                                                    托管维护（避免设置成具体数字导致客户端报错）。

  ↳ cMaxReuseTimes      "64-128"                    单条连接最大复用请求数。当一条连接处理的请求达到这
                                                    个次数后，会自动废弃并重建，防止单条连接寿命过长。

  ↳ hMaxRequestTimes    "600-900"                   HTTP 层的最大请求复用次数。双重保险，配合请求次数
                                                    到期主动“换马甲”。

  ↳ hMaxReusableSecs    "1800-3000" (30~50分钟)     单条连接的最长存活时间（秒）。即使没达到请求数上限，
                                                    时间到了也会自动无缝切换新连接，避开网关超时拦截。

XHTTP Manager V4.8.8
====================

本版本以用户上传并实际部署的 XHTTP_Manager_V4.8.7.zip 为唯一代码基础继续优化；不使用 V4.8.5，也不把两个 V4.8.6 整包互相覆盖。保留原有管理器代码和 7 种协议、Xray 核心管理、Cloudflare Tunnel、节点信息、完整卸载及本地订阅功能。

本次重点修复
------------
1. 快捷命令：每次打开管理器菜单时，检查并持久化当前正在运行的完整 xhttp.sh、core.sh、tunnel.sh；修复或创建 /usr/local/bin/xhttp。快捷命令指向本实例的持久化脚本，不再只在安装节点时创建。
2. 进程替代启动兼容：支持 `bash <(curl ...)` 这类启动方式，从当前脚本及已解析模块保存运行文件；本地订阅辅助文件缺失时，尝试从配置的 RAW_BASE_URL 下载并进行 Python 语法检查。
3. 本地订阅生成器：修复缺失时的补齐流程；自动兼容 4.8.7 和 4.8.8 实例标记，聚合扫描 /etc 下的 xhttp、xhttp-N 节点。
4. 本地订阅服务：确保 local_sub_server.py 与生成器都安装到实例专属库目录，再创建 systemd/OpenRC 服务。
5. 实例识别：对带有效 XHTTP 实例标记、state/config 和专属 Xray 二进制的旧实例，放宽对历史模块文件的依赖；仍要求服务 ExecStart 与实例专属路径匹配，避免接管无关服务。
6. Python 3：纳入依赖检查与安装，避免订阅辅助程序因解释器缺失而中断。

使用方式
--------
1. 将完整 ZIP 上传到 VPS 并解压。
2. 进入解压目录，以 root 执行：bash xhttp.sh
3. 启动时会检查管理器运行文件并创建/修复 `xhttp` 快捷命令。
4. 之后可直接执行：xhttp
5. 在菜单 7 选择“重置安装本地IP订阅链接”，完成后会显示 Clash/Mihomo、Sing-box、聚合订阅三个真实地址。

注意事项
--------
- 若 /usr/local/bin/xhttp 已被其他非本项目程序占用，程序会拒绝覆盖并给出提示；不会静默覆盖无关命令。
- 本地订阅服务需要 VPS 防火墙/云安全组允许所选 TCP 端口入站，程序不会擅自改动防火墙。
- 完整卸载仅针对经验证的 xhttp / xhttp-N 专属路径和服务；不会主动删除 /etc/s-box/、sing-box.service 或无关 Cloudflared。
- 本包已完成本地语法和模拟功能测试，但没有在用户 VPS 上执行真实 systemd/OpenRC 安装、重启、客户端连接或卸载测试；不能宣称所有 VPS 环境均已实机验证。
